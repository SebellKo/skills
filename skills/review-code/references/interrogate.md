# Interrogate 리뷰어

이 변경이 깨지는 조건을 찾고 실제 코드 실행으로 증명한다. 동일한 목표·대상 버전과 자신의 재현 공간을 사용한다.

## 필요한 원칙을 읽는다

메인과 이 리뷰어는 아래 조건에 맞는 원칙 파일을 직접 읽는다. 이미 현재 맥락에서 읽은 파일은 다시 읽지 않는다. 링크가 없으면 설치 목록에서 같은 이름을 찾고, 그래도 없으면 누락을 알린다.

| 적용 상황 | 읽을 원칙 |
| --- | --- |
| 실행 결과로 결함 여부를 판정할 때 | [prove-it-works](../../principles/principle-prove-it-works/SKILL.md) |
| 기존 테스트를 평가하거나 재현 검사를 작성할 때 | [test-behavior-not-implementation](../../principles/principle-test-behavior-not-implementation/SKILL.md) |
| 증상의 발생 지점을 추적할 때 | [fix-root-causes](../../principles/principle-fix-root-causes/SKILL.md) |
| TypeScript 코드를 읽을 때 | [typescript-best-practices](../../typescript-best-practices/SKILL.md) |

원칙의 수정 지침은 원인 분석과 수정 방향 제안에만 적용한다. 리뷰 중 제품 코드는 수정하지 않는다.

## 검토와 반환

- 사용자 흐름과 계약을 따라 정상·실패·경계 조건을 조사한다. 변경과 관련된 권한, 비동기 순서, 상태 공유, 데이터 보존, 다른 호출부를 살핀다.
- 실패하는 테스트, 재현 스크립트 또는 명령으로 실제 결과와 기대 결과의 차이를 확인한다.
- 기대 결과를 요구사항·계약에서 도출하고, 기준 코드와 같은 조건으로 비교해 이번 변경에서 생기거나 악화됐는지 확인한다. 기존 동작이나 직접 만든 테스트의 기대값이 옳다는 가정만으로 회귀를 판정하지 않는다. 의도된 동작 변경인지도 확인한다.
- 재현용 변경은 배정된 공간에만 둔다. 제품 구현을 고쳐서 확인하거나, 실제 사용자 경로와 무관한 모의 실패를 근거로 삼지 않는다.
- 실행하지 않은 의심은 검증된 지적에서 제외한다. 실행 환경이 없어 확인하지 못한 중요한 후보는 원인과 필요한 조건을 미확인 범위에 남긴다. 스타일·명명 취향이나 가상의 미래 변경을 위한 제안은 제외한다.

각 결함은 제목, 파일·줄, 대상 버전, 재현 사전 조건·작업 디렉터리·정확한 명령, 실제 출력, 기대 결과의 근거, 사용자 영향과 함께 반환한다. 긴 로그는 핵심 결과와 원본 위치로 전달한다. 실행 차이만 확인하고 계약 위반을 입증하지 못했다면 확인 필요로 남긴다. 검증된 결함이 없으면 실제 확인 범위와 미확인 범위만 반환하며 지적을 만들기 위해 탐색을 늘리지 않는다.
