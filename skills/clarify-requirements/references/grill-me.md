# grill-me 인터뷰 적용

Matt Pocock의 `grill-me` → `grilling`에서 가져온 의사결정 트리와 질문 라운드를 요구사항 도출에 적용한다.

## 질문을 구성한다

이미 결정했거나 위임한 항목은 다시 묻지 않는다. 남은 제품 결정이 어떤 앞선 답에 의존하는지 파악하고, 선행 조건이 해결된 질문들을 한 라운드로 묶는다. 질문이 많으면 주제별로 나눈다.

질문마다 번호, 결정할 내용, 관련 근거, 추천안과 이유를 제시한다. 핵심 흐름을 완성하는 범위를 추천하고, 추가 기능·설정이 누구에게 필요한지 확인한다. 선택에 따른 사용자 경험이나 범위 차이를 설명하며, 구현 편의를 이유로 핵심 목표를 축소하거나 확인 없이 합의한 기능을 제외하지 않는다.

예:

> Q1. 확정된 예약도 취소할 수 있어야 하나요? 시안에는 취소 버튼이 있지만, API는 대기 중인 예약만 취소할 수 있습니다.
>
> 추천: 이번에는 대기 중인 예약만 취소하도록 정리합니다. 현재 API 범위에서 제공할 수 있습니다. 확정된 예약 취소가 핵심 목표라면 백엔드 변경을 의존성으로 포함해야 합니다.

## 답에 따라 갱신한다

추천은 제안이다. 답변 없음이나 시간 경과를 동의로 처리하지 않는다. 사용자가 판단을 위임한 항목은 근거를 적어 결정한다.

답을 받으면 요구사항과 완료 조건을 갱신하고, 새로 답할 수 있게 된 질문을 묻는다. 예를 들어 취소 가능 상태가 미결정이면 그 상태를 전제로 한 환불 정책은 이후에 묻는다. 앞선 답이 바뀌면 영향을 받는 요구사항도 다시 확인한다.

사용자가 모르는 항목은 필요한 근거, 확인할 주체, 영향을 받는 범위를 남긴다. 같은 질문을 반복하지 않고 독립적으로 조사·정리할 수 있는 부분을 계속한다. 질문은 이번 제품 범위에 한정한다.
