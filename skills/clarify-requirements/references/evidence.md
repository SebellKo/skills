# 디자인과 백엔드 자료 조사

제품 동작과 완료 조건에 영향을 주는 부분을 조사한다. 아래 항목을 모두 질문하는 체크리스트로 사용하지 않는다.

사용자가 제공한 백엔드 PR은 바로 참조할 수 있는 API 계약으로 취급한다. 병합·배포 여부를 별도로 확인하거나 미결정 사항으로 남기지 않는다.

| 자료 | 확인할 것 | 해석의 한계 |
| --- | --- | --- |
| 디자인 시안 | 대상 화면·노드, 진입과 종료, 사용자 행동, 문구, 보이는 상태, 관련 주석·프로토타입 | 정적인 화면 하나로 저장 방식, 권한, 오류, 반응형 동작까지 확정할 수 없다. |
| 백엔드 PR | 본문, 참조한 커밋, 관련 diff, 요청·응답 스키마, 검증·권한·오류, 테스트, 필요한 논의 | 명시되지 않은 제품 정책은 추정으로 구분한다. |
| 백엔드 저장소 | 확인한 브랜치·커밋, 라우트에서 서비스·모델로 이어지는 경로, 계약과 테스트, 관련 호출부 | 조사한 범위 밖의 지원 여부는 미확인이다. |

사용자 흐름에서 관련된 빈틈을 찾는다. 저장 흐름에는 검증 실패·중복 제출·실패 후 입력 보존이, 목록에는 빈 상태·조회 실패·페이지 이동이, 상태 변경에는 허용된 이전 상태·권한·동시 변경이 중요할 수 있다. 관련 없는 상황을 새 요구사항으로 추가하지 않는다.
