# 버그 수정

[dev-mode의 공통 절차](../SKILL.md)에 따라 시작 전 Issue·화면 근거를 준비하고, 아래 작업 후 결과 PR을 게시한다.

기대 동작과 실제 동작의 차이를 재현하고 그 원인을 수정한다.

1. 기대 동작과 실패 조건을 확인한다. 제품 의도가 모호하면 `clarify-requirements`로 해당 부분만 정리한다.
2. `qa-feature`로 현재 실패를 실제 사용 경로에서 재현한다. 입력·권한·순서·환경과 실제 결과를 구현 담당자에게 전달한다. 직접 재현이 어렵다면 로그나 테스트에서 조건을 좁히고, 재현하지 못한 사실을 밝힌다.
3. `implement-code`의 구현 담당자에게 먼저 원인 조사를 맡긴다. 관련 호출·상태 흐름을 추적하고 가설을 실행 결과와 대조하게 한다. 메인은 원인을 뒷받침하는 근거를 확인한 뒤 수정을 진행시킨다. 근거 없이 방어 코드나 우회 처리를 쌓지 않는다.
4. 책임·인터페이스·상태 소유권을 바꾸는 수정이면 `design-code`로 관련 설계를 정리한다. 국소적인 원인 수정에는 독립 설계 비교를 강제하지 않는다.
5. `implement-code`로 수정과 관련 검사를 수행한다. 가능한 경우 원래 실패를 잡는 작은 회귀 테스트를 남긴다.
6. `review-code`로 수정과 주변 영향을 검토한 뒤, `qa-feature`로 원래 재현 조건과 영향받는 기존 흐름을 다시 확인한다.

**완료:** 원인을 설명할 근거가 있고 원래 실패 조건에서 기대 결과를 확인했으며 관련 회귀가 없다. 원래 문제를 재현·확인하지 못했다면 수정 후보와 확인한 범위만 보고하고 해결을 단정하지 않는다.
