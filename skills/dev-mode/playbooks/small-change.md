# 단순 수정

목표가 명확하고 영향이 국소적인 변경을 필요한 검증과 함께 마친다.

1. 바꿀 위치·기대 결과와 현재 상태를 확인한다. 문구·간격·색상·국소적인 레이아웃처럼 결과가 명확하면 요구사항 인터뷰와 독립 설계를 반복하지 않는다. 모호한 선택만 확인한다.
2. 관련 사용처를 확인한다. 실제 원인이 버그이거나 동작·계약·상태 변경이 필요하면 해당 플레이북으로 전환한다. 권한이나 데이터 처리 변경을 작은 diff라는 이유로 이 흐름에 남기지 않는다.
3. `implement-code`로 범위가 좁은 수정을 위임하고 관련 구현 검사를 수행한다.
4. `qa-feature`로 변경 부분과 직접 영향을 받는 동작을 확인한다. UI는 ego lite에서 필요한 화면·상태·크기로 확인한다. 다른 종류의 수정은 실제 사용하는 인터페이스로 검증한다.
5. 공유 컴포넌트·공통 스타일 등 다른 사용처에 영향이 있거나 변경에서 실질적인 위험이 드러나면 `review-code`를 추가하고 필요한 QA를 다시 수행한다. 독립 리뷰를 실행할 때는 세 역할을 그대로 사용한다. 국소적인 변경이라 생략하면 그 이유를 짧게 남긴다.

**완료:** 지정한 결과를 확인했고 관련 동작을 보존했다. 검증 환경이 없어 확인하지 못한 상태는 작은 작업이어도 통과로 처리하지 않는다.
