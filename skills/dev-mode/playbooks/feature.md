# 기능 구현

새로운 동작이나 합의한 동작 변경을 완성한다.

1. `clarify-requirements`로 목표·범위와 관찰 가능한 완료 조건을 정리한다. 제공된 요구사항은 활용하고, 설계를 좌우하는 미결정을 먼저 해소한다.
2. 코드 변경 전에 `qa-feature`의 변경 전 확인으로 현재 흐름, 유지할 동작, 기존 문제와 미확인을 파악한다. 새 기능에 이전 동작이 없으면 연결되는 기존 흐름을 확인한다.
3. `design-code`로 독립 설계를 비교·통합한다. 유효한 기존 설계가 있으면 이어받는다. 설계에서 영향 범위가 넓어졌다면 구현 전에 필요한 기준 관찰을 보충한다.
4. `implement-code`로 구현하고 구현 검증을 수행한다. 작업 단위와 순서는 메인이 읽은 `sequence-verifiable-units`에 따른다.
5. `review-code`로 독립 리뷰한다. 메인이 채택한 문제를 수정하고 영향받는 리뷰와 검사를 다시 확인한다.
6. `qa-feature`로 새 기능의 완료 조건과 관련 기존 동작을 검증한다. 수정이 필요하면 원인에 맞는 단계로 돌아가고 최종 코드에서 다시 확인한다.

**완료:** 합의한 요구사항을 충족하고 필요한 구현 검사·리뷰 수정·기능 및 회귀 QA를 마쳤다. 새 기능에서 관찰하지 못한 과거 동작을 회귀 통과 근거로 삼지 않는다.
